# Estrategia de pruebas para Buggy Cars

**Criterio: testing basado en riesgo** (ISTQB). Primero lo que más impacto tiene si falla (registro, login, voto) y, en cada caso, el **nivel más bajo** que lo cubra: probar una regla en la API es más rápido y estable que en la pantalla.

| Nivel           | Qué más probaría                                                                                                                                                                                                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **API**         | Registro (`POST /users`) con **valores límite** en la contraseña (5, 6 y 7 caracteres) y en el usuario (50/51 caracteres), usuario repetido; voto (`POST /models/{id}/vote`) dos veces o sin token; paginación (`/models?page=0` hoy da **502**). La UI esconde estos casos, pero la API los acepta o se cae |
| **Contrato**    | Un JSON Schema por respuesta (`/models`, `/models/{id}`, `/users/current`), como en Petstore                                                                                                                                                                                                                 |
| **UI**          | Perfil, página de marca (orden y paginación) y **logout en todas las páginas** (ya falla en el ranking: BUG-07, y deja datos visibles en el perfil: BUG-08)                                                                                                                                                  |
| **Performance** | `/models/{id}` tarda hasta **4,4 s** porque manda todos los comentarios sin paginar (F-02): prueba de carga con un umbral (por ejemplo, p95 < 2 s)                                                                                                                                                           |
| **Seguridad**   | Expiración de la sesión, token inválido después del logout y comentarios con HTML/scripts (XSS)                                                                                                                                                                                                              |

**Qué dejaría fuera de la automatización:** lo visual y la claridad de los textos (mejor con **pruebas exploratorias**, que encontraron BUG-03 y BUG-05); los **valores del catálogo** (como la velocidad del Diablo, BUG-04), que cambian con cada edición; y cualquier **prueba de carga sobre el sitio público**, porque afectaría a otros usuarios.
